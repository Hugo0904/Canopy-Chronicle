# 資料格式

這份是 Skill 文字和三支腳本共用的格式。腳本靠它解析，改格式要兩邊一起改。

## 位置

紀錄根目錄預設是使用者家目錄下的 `.canopy-chronicle/`。環境變數 `CANOPY_CHRONICLE_HOME` 有值時改用它（測試用暫存資料夾就靠這個）。

```text
<根目錄>/
  config                 選用，容量設定，見下方
  <專案代號>/
    PROJECT.md           手寫：專案名稱與範圍，腳本不改它
    PINNED.md            手寫：仍有效的決定、擱置中的事，腳本不改它
    INDEX.md             一行一筆；寫紀錄時追加，壞了可由腳本整份重建
    2026-11.md           當月紀錄，只往下追加
    archive/2026-08.md.gz  已封存的舊月份
```

專案代號只用小寫英數與連字號，例如 `my-app`。

## PROJECT.md

```markdown
# 專案顯示名稱

範圍：這份紀錄涵蓋哪個資料夾或哪一塊功能，一兩句
建立：2026-11-26
```

新對話靠「範圍」判斷自己屬於哪個專案代號。一個資料夾裡有兩個各自獨立的大功能時，可以各開一個專案代號。

## 一筆紀錄

寫在當月檔 `YYYY-MM.md` 的最後面。

```markdown
## 2026-11-26-01 標題一句話
- 類型：決定
- 關鍵字：結帳, 折扣, 四捨五入
- 相關：commit abc1234、任務編號、檔案區域（沒有就省略這行）

內容：做了什麼或決定了什麼，寫到事後只看這一筆就看得懂。
原因：為什麼；否決了哪些做法、各自為什麼不採用。
```

規則：

- 標題行固定是 `## ` 加編號加一個空白加標題。編號是 `YYYY-MM-DD-NN`，NN 是當天第幾筆，從 `01` 起、兩位數。
- 標題和關鍵字不可含 `|`。
- `- 類型：` 必填，只能是這六個之一：`完成`、`決定`、`要求`、`踩坑`、`驗收`、`擱置`。
- `- 關鍵字：` 必填，一到六個，用半形逗號分隔；單一關鍵字裡可以有空白。寫之後會拿來搜尋的詞：功能名、畫面名、錯誤訊息裡的字。搜尋只比對索引裡的標題與關鍵字，不比對內文。
- 欄位行緊接在標題行下面、中間不空行，冒號用全形 `：`。「相關」是選填。
- 內文自由書寫，建議 5 到 15 行。不可出現以 `## ` 開頭的行。
- 已寫入的紀錄不改內文。寫錯了就追加一筆更正，並在內文寫明更正哪一筆的編號。

六種類型各記什麼：

| 類型 | 記什麼 |
| --- | --- |
| 完成 | 做完的事：結果，以及位置（分支、版本、檔案區域） |
| 決定 | 選了什麼、為什麼、否決了哪些方案 |
| 要求 | 使用者提的需求、指正或同意，保留關鍵原話 |
| 踩坑 | 症狀、真正原因、怎麼解 |
| 驗收 | 怎麼驗的、結果、上線的版本 |
| 擱置 | 說好先不做或試過後放棄的事，以及原因 |

## INDEX.md

每筆紀錄一行，新的在下面：

```text
2026-11-26-01 | 決定 | 標題一句話 | 結帳, 折扣, 四捨五入 | 2026-11.md
```

五欄用 ` | ` 分隔：編號、類型、標題、關鍵字、所在檔案（相對於專案資料夾；封存後是 `archive/2026-08.md.gz`）。

寫一筆紀錄時，同時把這一行追加到 `INDEX.md`。索引可以由 `maintain.sh` 從紀錄檔整份重建，所以索引壞了不會掉資料。

## PINNED.md

現況，不是歷史。新對話開場會看到它，所以要短。

```markdown
# 釘選

## 仍有效的決定
- 金額一律用整數分計算，不用浮點（2026-11-26-01）

## 擱置中
- 匯出 PDF 先不做，等版型定案（2026-11-20-03）
```

- 每行一句話，後面括號放紀錄編號。
- 決定被推翻、擱置的事重啟或確定不做時，改掉或刪掉這一行，並另外追加一筆紀錄說明。
- 整份不超過 `PINNED_MAX_LINES` 行。

## config

選用。一行一個 `名稱=數字`，`#` 開頭是註解。沒有這個檔或缺某一項時用預設值。

| 名稱 | 預設 | 意思 |
| --- | --- | --- |
| `KEEP_MONTHS` | 3 | 最近幾個月的紀錄保留原文不封存（含當月） |
| `KEEP_MIN_ENTRIES` | 50 | 未封存的紀錄至少保留這麼多筆，不足就不封存 |
| `ARCHIVE_KEEP_MONTHS` | 12 | 封存滿幾個月才列入可刪清單。以月份檔名推算：距今滿 `KEEP_MONTHS` 加 `ARCHIVE_KEEP_MONTHS` 個月（預設 15 個月） |
| `PROJECT_MAX_KB` | 512 | 單一專案未封存的紀錄超過這個大小就提醒維護 |
| `PINNED_MAX_LINES` | 30 | `PINNED.md` 的行數上限 |

刪除的去處預設是 `<根目錄>/.trash/`，環境變數 `CANOPY_CHRONICLE_TRASH` 有值時改用它。移過去的檔案按專案代號分資料夾放，同名不覆蓋。

## 腳本

腳本在這個 Skill 的 `scripts/` 資料夾，只需要 POSIX sh；三支腳本共用同資料夾的 `lib.sh`。不帶 `--apply` 時一律只預演、不改任何檔案。

| 腳本 | 用法 | 做什麼 |
| --- | --- | --- |
| `status.sh` | `status.sh [專案代號]` | 唯讀。列出筆數、大小、是否超過上限、索引和紀錄檔有沒有對上、有沒有格式不合的紀錄。有問題時結束碼為 1；用法錯誤、專案或根目錄不存在時為 2 |
| `status.sh` | `status.sh --brief 專案代號` | 唯讀。印出開場摘要：`PINNED.md`、索引最後 10 行、怎麼查 |
| `maintain.sh` | `maintain.sh [--apply] [專案代號]` | 重建 `INDEX.md`；把符合條件的舊月份封存到 `archive/` |
| `prune.sh` | `prune.sh [--apply] [專案代號]` | 列出封存滿期限的檔案；帶 `--apply` 才把它們移到刪除的去處，不直接刪除 |

封存一個月份的條件：整個月份早於 `KEEP_MONTHS` 的範圍，而且封存後未封存的紀錄仍不少於 `KEEP_MIN_ENTRIES` 筆。封存只是壓縮搬移，索引那一行仍在，還是搜得到。
